## 1. 背景与问题

个人做小红书时，热点、选题、文案、封面、发布和复盘分散在多个工具里。热点看起来热，却不一定适合自己的账号；封面和排版耗时长；发布后的数据很少回到下一轮选题。

本产品把这条链路收成一个本机工作台：AI 负责发现、分析和起草，人负责判断、审核和发布。运营结果沉淀进本地知识库，供下一轮使用。

账号方向尚未确定。第一版用配置描述定位、读者和风格，先做小规模选题实验，再用本账号数据决定长期方向。

------------------------------------------------------------------------

## 2. 产品定位

**个人使用的小红书 AI 辅助运营工作台。**

-   使用者是账号运营者本人。
-   第一阶段通过 Codex 对话操作系统。
-   后续提供 Web 管理界面，复用同一套能力。
-   内容必须经人工确认后才能发布。
-   知识、草稿、图片和运营数据保存在本机。

------------------------------------------------------------------------

## 3. 目标用户与核心场景

### 3.1 目标用户

单人运营一个小红书账号。用户会自己判断选题、修改文案，并在发布前做最终确认。第一版不服务团队协作和多账号代运营。

### 3.2 核心场景

1.  用户说「看看今天适合我的热点」，系统收集真实素材，按账号条件筛出候选选题。
2.  用户选定一个选题，系统产出内容脚本、3～6 页文案和可预览的图文卡片。
3.  用户改完并明确确认后，系统协助发布，并留下版本和发布记录。
4.  用户录入这篇笔记的数据，系统按本账号历史写出复盘。用户确认后，结论进入知识库。
5.  用户询问账号定位、标题或封面做法，系统引用知识库回答，并标明哪些是已有资料、哪些是本次工具结果、哪些是模型判断。

------------------------------------------------------------------------

## 4. 目标与非目标

### 4.1 产品目标

1.  用一条可追踪的流程走完：发现素材、判断是否适合账号、确定选题、写出图文、生成卡片、人工发布、复盘、沉淀知识。
2.  把采集结果、人工补充和其他平台灵感放进同一个素材池。
3.  让封面和排版成为独立步骤，缩短视觉制作时间。
4.  让复盘结论能回到下一轮分析和选题。
5.  知识库可阅读、可编辑、可迁移。

### 4.2 非目标

-   自动发布、自动评论、自动私信。
-   多账号、团队权限和数据大屏。
-   用模拟数据填补采集失败。
-   把其他账号的爆款数据当成自己账号的结论。
-   直接搬运他人正文作为待发布内容。
-   第一版自动采集抖音、B站、微博、知乎。
-   以长期维护 Cookie 作为日常操作。

------------------------------------------------------------------------

## 5. 产品原则

1.  **AI 起草，人工决定。** 选题、文案、图片和策略都可以由 AI 生成；进入发布或写入长期策略前，必须由人确认。
2.  **适合账号优先于单纯热门。** 分析要同时看热度、账号匹配、本账号历史、差异化和制作成本。
3.  **真实来源可追溯。** 每条素材保留平台、进入方式和采集状态。失败就是失败。
4.  **本账号数据解释本账号。** 复盘使用自己的曝光、阅读、点赞、收藏和评论。
5.  **工具可替换。** 换采集器、模型或出图工具时，用户看到的步骤和产物保持不变。
6.  **账号定位可配置。** 定位、读者、内容类型和语气写在配置里，不写死在对话或代码中。

------------------------------------------------------------------------

## 6. 主流程

八步顺序执行。上一步没有合格产物时，下一步不开始。第 8 步确认后的知识，供下一轮第 2 步和第 3 步使用。

``` text
1 热点与素材发现
        ↓
2 热点分析与账号适配
        ↓
3 选题决策与内容策划
        ↓
4 图文内容生产
        ↓
5 视觉设计与卡片生成
        ↓
6 人工审核与发布
        ↓
7 数据跟踪与效果复盘
        ↓
8 知识沉淀与策略优化
        ↓
   回到第 2 步和第 3 步
```

**Web 侧栏（用户动线）：** 首页 → 热点 → 创作（一键成文六步：选题、写作、去 AI 味、配图、排版、发布；及一键成图）→ 工具 → 资源 → 设置。分组含义、路由规划与八步映射见 [XHS_AI_Operator_导航与信息架构.md](XHS_AI_Operator_导航与信息架构.md)。

## 7. 功能需求

### 7.1 热点与素材发现

用户要在一个素材池里看到今天可参考的内容。

**来源**

-   小红书公开热点和公开内容，由已通过验证的采集工具获取。
-   人工补充：笔记链接、截图、文案、竞品账号。
-   抖音、B站、微博、知乎：第一版只接收人工放入的链接、截图或文案，用作趋势和灵感。

**需求**

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F1.1 | 采集结果和人工输入进入同一素材池 | P0 |
| F1.2 | 每条素材记录平台、进入方式、时间和原始状态 | P0 |
| F1.3 | 相同链接或笔记 ID 合并为一条 | P0 |
| F1.4 | 采集失败、为空、需要登录或识别为模拟数据时，状态可见，且该条不进入选题 | P0 |
| F1.5 | 用户可查看失败原因 | P0 |
| F1.6 | 对已选定的参考笔记，可归档封面、图片或视频到本地 | P1 |
| F1.7 | 关键词搜索、笔记详情和评论在对应工具验证通过后可用 | P1 |

**完成标准：** 一次免登录热点采集能产生至少 5 条带标题和可打开链接的真实素材；人为制造一次浏览器失败时，素材池不新增笔记，状态为失败。

### 7.2 热点分析与账号适配

用户要知道「这个热点值不值得我做」，而不是只看到一个热度排行。

分析只使用状态为成功或部分成功的真实素材，并读取账号配置和本账号历史笔记。

**每条候选至少包含**

-   热度：近期讨论量、互动表现、增长趋势。缺数据时标明缺失。
-   账号匹配：是否符合定位、目标读者和内容风格。
-   历史表现：本账号过往相似内容的曝光、互动和转化。没有历史时明确写「尚无本账号数据」。
-   差异化：是否存在新的切入角度。
-   制作成本：文案、图片和预计耗时。
-   适配度：高、中、低，并给出一句理由。

**需求**

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F2.1 | 输出热点分析报告 | P0 |
| F2.2 | 输出不少于 5 个候选选题，每个带适配度 | P0 |
| F2.3 | 报告区分事实、知识库结论和模型判断 | P0 |
| F2.4 | 失败素材不参与评分 | P0 |

### 7.3 选题决策与内容策划

用户从候选里选定一个主题后，系统给出可以开工的方案。未选定前不生成完整图文。

**选题方案包含**

-   目标读者和用户需求。
-   内容角度、核心观点和差异化表达。
-   标题方向、正文结构和内容节奏。
-   图文页数、每页核心信息和行动引导。

**需求**

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F3.1 | 用户可选择、改写或否决候选选题 | P0 |
| F3.2 | 选定后生成选题方案和内容脚本，并保存 | P0 |
| F3.3 | 选题可回溯到素材池中的来源 | P0 |

### 7.4 图文内容生产

AI 生成草稿。草稿不是待发布版本。

**需求**

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F4.1 | 生成标题、正文、摘要和标签 | P0 |
| F4.2 | 按内容类型选用模板：知识科普、教程步骤、观点分析、经验分享 | P0 |
| F4.3 | 把文案拆成 3～6 页，每页有核心信息 | P0 |
| F4.4 | 页面内容以结构化数据交给视觉步骤 | P0 |
| F4.5 | 用户可修改任意一页后重新生成后续页面 | P1 |

文案使用用户自己的角度重写。参考笔记的原文只留在素材和案例里。

### 7.5 视觉设计与卡片生成

这一步单独处理封面和排版，不在写文案时顺便出图。

**需求**

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F5.1 | 根据页面内容生成封面创意、布局和视觉风格 | P0 |
| F5.2 | 用固定模板渲染标题、正文、图标和装饰 | P0 |
| F5.3 | 按需生成插画或背景 | P1 |
| F5.4 | 自动检查文字溢出、图片尺寸、字体和页面一致性，并列出问题 | P0 |
| F5.5 | 输出封面、正文配图和完整预览 | P0 |

视觉方案和图片生产是两件事。方案确定页面怎么排，生产负责把页面做成图片。

### 7.6 人工审核与发布

用户对最终质量负责。系统提供检查和发布动作，不代替确认。

**审核范围**

-   事实是否有来源，判断是否被写成事实。
-   是否把他人正文直接当作自己的笔记。
-   标题、正文、图片、排版是否符合当前平台规范。
-   文字溢出和页面不一致是否已处理。

**需求**

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F6.1 | 审核意见和待发布预览放在一起 | P0 |
| F6.2 | 用户必须针对当前笔记和当前版本明确确认 | P0 |
| F6.3 | 标题、正文或图片一旦修改，原确认失效 | P0 |
| F6.4 | 确认后可通过发布工具辅助发布 | P0 |
| F6.5 | 保存发布时间、结果、笔记链接和内容版本 | P0 |
| F6.6 | 发布失败留下原因，不自动连续重试 | P0 |
| F6.7 | 不提供「发布全部待发布内容」或长期授权 | P0 |

### 7.7 数据跟踪与效果复盘

用发布后的实际数据检查选题和内容是否有效。

**指标：** 曝光、阅读、点赞、收藏、评论。涨粉可记，第一版允许为空。

**需求**

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F7.1 | 用户可按笔记录入指标 | P0 |
| F7.2 | 系统对比不同选题、标题、封面和内容结构 | P0 |
| F7.3 | 对比基线是本账号历史；没有历史时只描述这一篇 | P0 |
| F7.4 | 输出单篇分析、周期报告和优化建议 | P1 |
| F7.5 | 原因标为观察或假设，并写明依据的笔记 | P0 |

第一版的指标由人工录入。自动拉取平台数据放到后续版本，且必须先验证获取方式。

### 7.8 知识沉淀与策略优化

把值得复用的结果留在知识库里，并在下一轮分析时被检索到。

**可沉淀的内容**

-   优秀笔记成为爆款案例。
-   账号表现更新账号画像和历史数据。
-   有效的内容结构成为模板。
-   经确认的复盘结论更新运营策略。

**需求**

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F8.1 | 入库前进入待确认区，用户通过后才成为正式知识 | P0 |
| F8.2 | 每条知识保留来源、日期、类型和状态 | P0 |
| F8.3 | 用户可按问题检索知识，并看到来源文档 | P0 |
| F8.4 | 检索不到时明确说明没找到，不编造知识库结论 | P0 |
| F8.5 | 已确认的策略会出现在后续的适配分析和选题里 | P1 |

知识类型包括：账号资料、爆款案例、运营方法、内容资产、运营数据。

### 7.9 机器人助手

机器人是第一阶段的操作界面。用户用自然语言发起或继续任意一步。

**需求**

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F9.1 | 能从一句话进入对应步骤，例如查热点、写选题、改文案、记数据 | P0 |
| F9.2 | 能查看当前任务停在哪一步、等待什么 | P0 |
| F9.3 | 回答区分知识库、实时工具结果和模型判断 | P0 |
| F9.4 | 对话和任务结果被保存，关闭后可以继续 | P0 |

## 8. 关键体验规则

1.  用户随时能看到任务状态：等待执行、执行中、等待补充、等待确认、完成、拒绝、失败、已取消。
2.  失败信息用日常语言说明下一步，例如「热点采集失败，本次没有新素材」或「登录已失效，深度采集已停止」。
3.  候选选题、脚本、文案和图片都可以退回上一步修改。
4.  一次确认只覆盖当前笔记的当前版本。
5.  账号定位为空时，系统仍可做选题实验，并在适配分析里写明定位未确定。

## 9. 第一版范围

第一版要跑通一条真实笔记，不要求所有外部工具同时可用。

| 版本切片 | 用户能完成的事 | 依赖 |
| --- | --- | --- |
| 可用的助手 | 在 Codex 中提问，得到模型回答 | 本机助手和模型 |
| 可用的知识库 | 放入一份资料，提问时得到带来源的回答 | 上一项 |
| 可用的创作闭环 | 从一条真实热点得到适配分析、选题、3～6 页文案和可预览图文 | 免登录热点采集通过 |
| 可用的发布闭环 | 人工确认后发布，录入数据，确认复盘并写回知识库 | 发布工具通过 |

深度搜索、评论、素材下载和每日爆款多源采集，各自验证通过后才出现在对应步骤里。未通过时，该能力保持关闭，前面的步骤仍可使用人工素材继续。

## 10. 第一版验收

验收看用户是否得到运营产物。

| 验收项 | 通过标准 |
| --- | --- |
| 对话 | 用户在 Codex 中完成一次运营提问并得到回答 |
| 知识问答 | 回答引用知识库文档；没有资料时说明没找到 |
| 素材池 | 真实热点和人工输入在同一列表；失败状态可见 |
| 适配分析 | 至少 5 个候选，各有适配度和理由 |
| 选题脚本 | 用户选定后得到选题方案和内容脚本 |
| 图文草稿 | 标题、正文和 3～6 页页面内容齐全 |
| 视觉预览 | 封面、配图和完整预览可查看，排版问题被列出 |
| 发布 | 未经当前版本确认时不能发布；确认后有发布记录 |
| 复盘 | 报告使用本账号指标，并经过确认后进入知识库 |

## 11. 后续版本

-   Web 侧栏按 [导航与信息架构](XHS_AI_Operator_导航与信息架构.md) 落地：热点（当日热点、新闻爆点）、创作（一键成文、一键成图）、工具、资源四库。
-   定时收集小红书公开热点。
-   其他平台的自动采集，前提是尽量免费、不把长期 Cookie 维护当作日常步骤、能输出结构化数据。
-   指定博主和竞品的深度观察。
-   经验证的平台数据自动回收。
-   更强的知识检索和去重。

## 13. 成功标准

第一版上线后的使用成功，是用户能独立完成下面这条闭环：

1.  拿到一批真实热点，并看清哪些采集失败。
2.  选出一个适合当前账号、成本可接受的选题。
3.  得到可修改的图文草稿和预览。
4.  亲手确认并发布。
5.  用这篇笔记的数据形成一条可复用的经验。

在账号方向仍未确定时，成功还包括：这些实验的选题、笔记和数据都留在本机，能够支持之后决定长期内容方向。
